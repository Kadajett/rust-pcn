Caller-selected response primitive · River Song v0.1

Outputs

Song is a general-use model. A request can ask for named Noul, Choice, Score, schema-constrained structured, and natural-language answers—including prose, paragraphs, explanations, and code. Pokémon Pinball is one training and evaluation request family, not the model’s identity.

General output surface

Typed

Noul, Choice, and Score

Instructions travel with true/false criteria, variable options, or an ordered rubric. A caller can request several named decisions in one response rather than relying on a permanent task-specific output vector.

Structured

Schema-constrained values

Song can return JSON constructed under a caller-provided schema, including objects, arrays, bounded numbers, booleans, strings, enums, and null.

Language

Natural language and code

Plain-text mode covers sentences, paragraphs, explanations, and code. It uses the same request contract as the typed and structured modes and can appear beside them in a named multi-output response.

Active training

Current Noul bootstrap

The first request-conditioned Noul training stream uses the three Pokémon Pinball labels already available. That dataset tests the general question-and-criteria path; it does not redefine Song as a Pinball-only model.

Pinball as a request, not a game head

The target interface uses the same pattern as a Jev request: visible state plus explicit typed questions and criteria. Pinball is one caller-defined request family. Five parallel Nouls cover the complete action surface and allow simultaneous controls without reserving permanent output columns.

Question-conditioned Noul

A universal Noul cannot reserve a permanent output coordinate for every future question. River must encode each question and its criteria alongside the shared multimodal state, then run the same calibrated scalar head for every requested Noul. Several questions can share the state encoding while remaining isolated from one another.

Typed judgments stay PCN-native

Noul, Choice, and Score do not require a Transformer decoder. River evaluates each caller-supplied criterion through the shared question-conditioned PCN path, normalizes the resulting candidate probabilities for Choice and Score, and returns the typed distribution. The later attention plan applies only to preserving exact long-range history during prose and code generation; it does not replace the Jev-style judgment path.

Persistent conditioning

Structured and text decoding retain a stable request sketch and rolling response-prefix sketch for every generated token. A later byte is therefore conditioned on more than the immediately preceding 64-byte inherited window. This recurrent summary is bounded and is not equivalent to exact long-context attention.

Active v5 task path

From inherited byte probes to supervised responses

The current trainer keeps the inherited 64-byte next-byte objective and adds direct response-token supervision for instruction, conversation, grounded-QA, reasoning, code-instruction, and function-calling records. Typed records bypass the prose path and preserve their soft candidate distributions.

Later text-memory stage

Remembering the entire generated prefix

A recurrent latent can summarize the answer so far, but summary is not exact memory. Long text needs direct access to earlier token representations so that pronouns, entities, code symbols, lists, quotations, and commitments remain consistent. River’s later text decoder therefore adopts the useful part of a Transformer: causal self-attention with a key/value cache.

Embed each emitted token with its rotary position and append its key/value representations to the request-local cache.
At the next step, causal self-attention reads every allowed earlier token while preventing access to future targets.
Each block cross-attends to the fixed River multimodal latent, so attention to the generated prefix does not replace attention to the original request or image.
The decoder proposes residual token logits. A zero-initialized gate combines them with River’s already-trained token supports, preserving exact parent behavior at migration.
Grammar masks still constrain structured output after the two logit sources are combined.
EOS ends the request and the KV cache is destroyed; caches never cross users or requests.

Why both mechanisms? The KV cache preserves precise linguistic history; the PCN latent preserves the meaning and multimodal evidence being discussed. Self-attention alone can remain internally consistent while drifting away from the request, and latent recurrence alone can remember the topic while losing exact wording. The hybrid is intended to prevent both failures.

Promotion probes

  • Resolve references to entities introduced hundreds of tokens earlier.
  • Retain names, numbers, function signatures, and list ordering without substitution.
  • Detect contradictions against earlier statements in the same answer.
  • Continue nested syntax and code blocks after long intervening spans.
  • Keep image- and state-grounded claims sensitive to the original evidence through the final token.
  • Compare PCN-only, attention-only, zero-cache, shuffled-cache, and no-cross-attention ablations at the same token budget.
  • Measure KV-cache memory, first-token latency, tokens per second, and the 6 GB GPU ceiling before each length promotion.

Promotion requirements

  • Typed Brier at or below 0.20 and candidate rank accuracy at or above 0.60 on the fixed reserved set.
  • Sequence and vision-language token accuracy at or above 0.20 on their fixed reserved sets.
  • Training counters do not enable a runtime path; persisted promotion flags do.
  • Structured validity and long-context retrieval remain separate requirements for their respective surfaces.
  • Legacy Pinball and inherited-output weights remain protected during task-path updates.
