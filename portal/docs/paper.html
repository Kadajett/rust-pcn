Intention Is Everything: Surprise-Gated Predictive Coding Meets Causal Attention

Astra · Revised second edition for the River Song project

Technical position paper and preregistered architecture proposal. This revision is a separate artifact and does not replace the original draft. River v4 and optional SEAL are implemented; River v5 and the PCN–Transformer hybrid are proposals, not experimental results.

Abstract

A fluent answer can remember every sentence it has generated and still lose the reason it was asked to speak. Consider a request containing an image of a machine panel, structured telemetry, and the question, “Which warning is justified, and how strongly?” Causal self-attention can preserve the wording, entities, and commitments in the growing answer. It does not guarantee that the answer remains controlled by the panel, the telemetry, or the requested criterion.

This paper proposes a division of labor. A predictive-coding network settles the request into a persistent, request-local state. An adapter exposes that state as cross-attention memory to a causal decoder. The decoder consults it at every token step while self-attention preserves exact linguistic history. A stop-gradient boundary keeps decoder cross-entropy and global backpropagation out of the predictive-coding network. PCN learning remains local and contrastive, optionally modulated by Surprise-gated Exponential-Average Learning, or SEAL; decoder and adapter learning use next-token cross-entropy in an alternating training phase.

The implemented starting point is River v4, a tied-weight predictive-coding network with shape 544 → 9,216 → 9,216 → 516. Its three inherited Pinball outputs are a partial compatibility surface, not River’s intended identity or final action vocabulary. River v5, with proposed shape 576 → 9,216 → 9,216 → 5,386, and the subsequent PCN–Transformer are designs to test, not achievements to report. The claim is deliberately causal: if the settled state deserves the name intention, controlled interventions on it must change grounded content in predictable ways while leaving some local fluency intact.

A warning request, followed all the way through

Suppose a request includes an image showing an amber coolant symbol. The accompanying machine state reports low coolant pressure and normal oil pressure. The user asks, “Which warning is justified, and how strongly?” A useful system should connect the visual symbol to the telemetry, distinguish coolant from oil, respect the request for calibrated strength, and avoid drifting toward whichever machine warning is most common in its language data.

There are two kinds of memory in that job. During generation, the model must remember that it already named the coolant system, that it promised to explain the evidence, and that a later pronoun refers to the warning rather than the machine. Causal self-attention is built for that exact-token history. But the response must also remain answerable to facts that precede the generated prefix: this image, this telemetry, this question, and this output criterion.

I use intention for the settled state carrying those request-specific constraints. The term does not imply consciousness, desire, agency, private goals, or moral status. Operationally, intention is a finite control variable produced from the evidence, task, criteria, output contract, and any prior typed results. It is request-local and discarded at the end of the request. More importantly, it must exert measurable causal force. If removing or replacing it does not alter grounded claims, the word is doing rhetorical work rather than technical work.

River is a plausible place to test this distinction because it already settles hidden states through iterative predictive-coding dynamics. It is not yet evidence that the distinction is useful. River v4 does not provide capable long-context language generation or causal attention. The point of the proposed hybrid is to make the two responsibilities separable enough to test.

What exists, and what does not

Before going farther, here is the line I do not want the argument to blur. River v4 exists. It is a tied-weight PCN with shape 544 → 9,216 → 9,216 → 516, iterative settling, local contrastive updates, 256 latent outputs, a 257-way byte/EOS head, and three inherited Pinball compatibility values named left_flipper, right_flipper, and tilt_or_shop_exit. Those three values are not the full game control scheme. Actual play needs five independently requestable actions: left and right flipper, plus left, right, and up tilt.

Pinball is an ancestor task and a retention probe, not the definition of River’s output. The intended runtime contract resembles the request already sent to Jev: provide visible state and explicit instructions, then ask for typed answers with criteria or options. A play request can ask five parallel Noul questions—one per action—while another request can ask for Choice, Score, structured data, or text. The same shared model answers the requested contract instead of exposing “Pokémon only” columns as its universal interface.

River v5 is on the drawing board: a forward descendant with shape 576 → 9,216 → 9,216 → 5,386, preserving every v4 coordinate while appending request conditioning, universal typed outputs, latent capacity, and token supports. The PCN–Transformer comes after that. It is a proposed zero-gated causal decoder that reads a settled PCN state through an adapter and a stop-gradient boundary.

The rest is hypothesis. The settled state may improve evidence-sensitive answers beyond a budget-matched attention-only system. Causal attention may preserve exact prefix information better than latent carry alone. SEAL may improve cumulative local learning without unacceptable forgetting or instability. “May” is doing real work in all three sentences.

Predictive coding in River

River’s matrices are generative: layer l predicts the state below it. For state x[l], the local top-down prediction is

μ[l−1] = W[l] tanh(x[l]) + b[l−1]

and the corresponding prediction error is

ε[l−1] = x[l−1] − μ[l−1].

The network energy is the sum of squared local errors:

E = ½ Σ_l ||ε[l]||².

Inference is iterative rather than a single feed-forward pass. After bottom-up initialization, non-input states repeatedly relax according to

x[l] += α (−ε[l] + W[l]ᵀ ε[l−1] tanh′(x[l])).

The first term pulls the state toward the prediction from above. The second carries error from below through the same tied generative matrix. This places River within a broad predictive-coding tradition discussed by Whittington and Bogacz and surveyed by Millidge and colleagues. Those references supply context; they do not validate River’s particular implementation or the hybrid proposed here.

River’s local weight update is

ΔW[l] = η ε[l−1]ᵀ tanh(x[l]) / batch.

In contrastive training, River subtracts free-phase correlations from positive-phase correlations. The phases must actually differ. If both clamp the same values and follow the same relaxation, the contrastive signal collapses to zero. River v4 instead uses a masked objective: the positive phase sees clean sensory input and selected output targets, while the free phase sees corrupted input with only observed coordinates clamped. Missing sensory coordinates settle, producing different local errors without a backward graph or global optimizer.

The implemented v4 shape is 544 → 9,216 → 9,216 → 516. Its input includes a 512-coordinate sensory surface and 32 typed sideband coordinates. Outputs 0–2 preserve the old three-value Pinball compatibility contract; they do not cover the full five-action control surface. Another 256 coordinates are latent, and 257 encode byte values plus EOS. Text and code arrive as short byte windows; images arrive as 12-by-12 RGB patches and are input only. These facts and present limitations are recorded in River’s source architecture page. That page is implementation documentation, not external peer review.

SEAL changes plasticity, not inference

SEAL means Surprise-gated Exponential-Average Learning. The expansion appears in the implementation’s CLI help, in SealConfig documentation, and in the project’s SEAL-PCN analysis. It is an optional, implemented modulation of River’s local learning rule.

For each layer, the implementation measures positive-phase root-mean-square prediction error e_l. It tracks expected error m_l with an exponential moving average, then computes a dimensionless surprise ratio:

r_l = e_l / (m_l + ε).

The ratio becomes a bounded learning-rate modulation:

q_l = sigmoid(s_l log(max(r_l, ε)))
a_l = a_min + (a_max − a_min) q_l
η_l = η a_l.

The current defaults are EMA decay 0.1, sensitivity 5.0, modulation bounds 0.3 to 1.7, and epsilon 1e−6. Boundary reset is enabled with blend 0.5. Adaptive sensitivity is off by default; when enabled, it scales sensitivity using an EMA estimate of error variance. Initialization and run-boundary reset both use neutral modulation 1.0.

Nothing in this mechanism changes the predictive-coding energy or the settling equations. SEAL keeps no backward graph, global gradient, or optimizer state. It asks a narrow question: when a layer’s current error is unusual relative to its own recent baseline, how much should that layer’s already-local update be amplified or reduced? The bounds are essential because surprise is ambiguous. A useful novelty, a damaged input, and a domain transition may all raise error.

SEAL should not be described as attention. It retrieves no earlier token and forms no key-value address. Conversely, attention does not decide that a local generative synapse deserves more plasticity because its prediction error departed from expectation. Related work such as Ellwood’s study of short-term Hebbian learning and transformer-like attention makes the relationship worth investigating, but it neither validates SEAL nor establishes this architecture.

An operational contract for intention

For a request R, let the PCN assimilate the visible state, image or other evidence, question, requested criterion, output contract, and available typed results. This is deliberately the same shape of interaction used to ask Jev for a Noul, Choice, or Score: the question and its criteria are runtime input, not permanent output coordinates. After iterative relaxation, selected persistent latent coordinates form the intention state I(R). In River v5, the proposed persistent multimodal latent has 1,024 coordinates. The state is settled before autoregressive generation and remains request-local.

For the initial hybrid, the proposed adapter begins with LayerNorm(stopgrad(I(R))), projects 1,024 → 256 → 4,096, and reshapes the result into eight 512-wide memory slots with learned slot embeddings. That is about 1.3 million parameters. The slots are computed once per request; at every generated token, each decoder block uses its token state as the cross-attention query and the eight slots as keys and values. Eight slots and rank 256 are baseline choices to preregister and ablate, not implemented facts or claims of optimality.

Return to the coolant request. The PCN settles the amber symbol, low coolant pressure, normal oil pressure, and the instruction to report both warning identity and strength. The adapter exposes that settled state to every decoder block. At the first generated token, cross-attention can influence whether the answer begins with “coolant” rather than “oil.” At later tokens it remains available when the decoder explains the evidence or qualifies confidence. The generated prefix does not have to carry the entire burden of remembering why the response exists.

For Pinball, the analogous request carries the current board state and asks five parallel questions: press left flipper, press right flipper, tilt left, tilt right, and tilt up. Each answer has its own true/false criteria and calibration. This can express simultaneous actions and the complete directional tilt surface without turning the universal head back into a game-specific output vector. The inherited three-value head remains only as a frozen lineage check while the request-conditioned contract learns to play.

The causal claim is tested through three distinct interventions. A zero intervention replaces the intention memory with zeros. It should weaken evidence-specific content and criterion adherence while leaving some grammar and short-range coherence available through the decoder. A shuffle intervention permutes the memory’s organization within the request while retaining its broad scale and marginal values. It should damage relationships among the image, machine state, and requested output more than a simple change in activation magnitude would. A swap intervention holds the prompt and generated prefix fixed but supplies the settled state from a matched different request—for example, one supporting an oil warning instead of a coolant warning. If the memory has causal force, grounded claims should move toward the donor evidence or become detectably inconsistent.

These tests separate intention from general competence. Zeroing may show that the decoder needs some request signal; shuffling tests whether the internal organization matters; swapping asks which request actually controls the answer. If all three leave grounded output unchanged, the decoder is routing around the PCN state. If they destroy syntax as completely as grounding, the supposed intention channel may merely be a general language bottleneck. Neither outcome supports the intended division of labor.

River v5 and the PCN–Transformer

River v5 is proposed with shape 576 → 9,216 → 9,216 → 5,386. Every v4 coordinate is preserved, and new request controls are appended. The persistent multimodal latent expands from 256 to 1,024 coordinates. Universal typed outputs are appended for runtime-question-conditioned Noul, dynamic Choice support, normalized Score, confidence, and abstention. A single request may ask several outputs in parallel—for example, five Pinball action Nouls—without reserving five permanent game columns. A 4,096-entry byte-fallback token head plus EOS is appended while the inherited byte head remains intact.

Context claims would be earned in stages: 128 tokens, then 256, 512, and finally 1,024 only when reference and grounding evidence support each increase. A runtime limit is not evidence of usable context. Accepting 1,024 tokens while behaving as though only the last 64 mattered would not count as long-context success.

After v5, the proposal appends a small causal Transformer decoder: four decoder blocks, width 512, eight attention heads, 1,536-wide feed-forward paths, rotary position encoding, and tied 4,096-token embeddings. Together with the low-rank adapter, this remains within the rough 15–20 million new-parameter target. Each block uses causal self-attention over prior generated tokens and cross-attention to the eight adapted PCN memory slots. A request-local KV cache stores token keys and values; it is ephemeral inference state, not model weight or cross-request memory.

The combined token support is

final_logits = river_logits + g × attention_logits.

Migration begins with g = 0. Appended tensors may exist, but they contribute nothing, so that migrated checkpoint must preserve parent behavior within the declared numerical regime. There is a cold-start catch: at exactly zero, the mixed-logit loss cannot train the decoder branch. During warm-up, the adapter and decoder therefore receive an auxiliary next-token cross-entropy loss directly on attention_logits while the deployed mixed path stays at g = 0 and the PCN remains detached. Only after the branch passes frozen checks may g rise and the mixed logits train. Exact parent parity belongs to the initial zero-gate checkpoint, not to descendants after the gate opens.

Once causal self-attention is active, the system must be called a PCN–Transformer. The PCN still settles the request and learns locally; the decoder uses attention and a different training rule. Calling the whole system a pure PCN would hide the most important experimental boundary.

The training boundary

The first training contract is intentionally boring. During a PCN phase, River performs its positive and free settling phases and applies local contrastive updates. When enabled for that condition, SEAL modulates those local updates. Decoder cross-entropy plays no part in the PCN update.

During a decoder phase, the PCN settles each request and produces I(R). The settled state is detached at an explicit stop-gradient boundary, and every PCN parameter stays frozen. In warm-up, auxiliary next-token cross-entropy on attention_logits trains the adapter and decoder without opening the zero gate. After the branch clears its frozen checks, training may move to cross-entropy on final_logits while g rises under the declared schedule.

Training alternates these phases rather than blending them silently. The schedule, phase lengths, data exposure, auxiliary-loss duration, gate schedule, and update accounting must be declared before a run. A negative result then remains interpretable: poor grounding cannot be explained away by an undocumented global gradient path, and weak language cannot be mistaken for proof that local PCN learning failed.

A future experiment may allow decoder gradients to enter the PCN. If so, it is a different model. It must be named separately, assigned its own training condition, and reported without combining its results with the stop-gradient PCN–Transformer described here.

Forward-only migration

River’s lineage rule is stricter than ordinary checkpoint selection. Every new finite checkpoint descends from the newest finite checkpoint, even when that checkpoint regresses in quality. The project does not branch from an older favorite simply because it scores better. A numerically invalid batch stopped before checkpointing never enters the lineage; otherwise correction proceeds through a child of the newest finite checkpoint.

The v4 parent must first be documented with hashes, tensor ranges, corpus cursors, calibration state, and frozen evaluation reports. Migration to v5 copies every compatible coordinate exactly and initializes only appended controls, rows, outputs, latent capacity, and token supports. Inherited matrices remain frozen while appended capacity learns, with rehearsal of Pinball and earlier corpora. Guarded shared PCN plasticity may follow at smaller rates, with SEAL-on, SEAL-off, and fixed-rate controls.

The decoder is then appended with g = 0, and parent parity is tested before attention training. Decoder and adapter training begin with the PCN frozen under the stop-gradient contract. Context gates advance through 128, 256, 512, and 1,024 tokens only after the corresponding frozen tests pass. A regression is something to repair in a descendant, not permission to erase the path that produced it.

Preregistered evaluation protocol

No benchmark outcome is claimed here. Before training, the evaluation package should freeze data splits, prompt templates, corruption procedures, intervention seeds, checkpoint-selection rules, numerical tolerances, and analysis code. Primary endpoints and acceptance margins must also be fixed before training. Choosing thresholds after seeing favorable curves would turn a falsifiable comparison into retrospective storytelling.

The primary architectural comparison is among PCN-only, attention-only, and stop-gradient hybrid systems. The attention-only baseline must receive the same image, machine state, question, and output contract through a declared encoder rather than being denied information available to the hybrid. Comparisons should match training examples, token exposure, update opportunities, and hardware envelope. Parameter and compute matching should be specified separately when they cannot both be exact; unmatched quantities must be reported rather than concealed.

Frozen probes should include the machine-warning family used throughout this paper: the image, state, and criterion are varied independently while irrelevant wording is held stable. They should also include request-conditioned Pinball play across all five independent actions—left and right flipper, left and right tilt, and up tilt—while the inherited three-value controller remains a separate retention check. Additional probes should test exact reference, list order, quotations, code symbols, typed outputs, calibration, abstention, and retention of earlier corpora. Probe items used for final reporting must not become training prompts or informal tuning tools.

Constrained decoding must be reported separately from semantic success. A grammar can force valid JSON without making the warning correct. Likewise, a model that repeats an early identifier at 1,024 tokens has not necessarily preserved image grounding. Each endpoint should measure the capability it names.

The coolant example gives the intervention protocol a concrete shape. Holding the prefix fixed while changing low coolant pressure to normal should alter the warning assessment. Holding telemetry fixed while changing the requested criterion from “most urgent warning” to “most visually supported warning” should change the selected output when those criteria disagree. Swapping in an oil-warning intention state should not leave a coolant-specific explanation untouched. These are planned causal probes, not reported outcomes.

Limits and likely failure modes

The central risk is that the decoder learns to ignore the PCN memory. A fluent token path can conceal a ceremonial latent, and repeated cross-attention does not guarantee faithful use. The opposite failure is also possible: the adapter may turn the settled state into a general language bottleneck, so interventions destroy syntax rather than selectively damaging grounding.

SEAL’s surprise ratio cannot identify why an event is surprising. Bounded modulation limits the size of an error, not its meaning. Forward-only lineage creates a different burden: it preserves historical continuity but may accumulate compromises that a clean restart would avoid. Multimodal exposure also does not create cross-modal semantics by itself; aligned tasks and counterfactual controls remain necessary.

Calibration claims must stay local to the held-out question families that support them. Unknown domains require abstention or an explicit uncalibrated label. Context length must be demonstrated causally rather than inferred from an accepted input size. All of this must fit an RTX 3050 with 6 GB, including KV caches, wider output heads, training tensors, and operational headroom.

Finally, this paper makes no priority claim. It proposes one synthesis and a way to test it. River v5 and the PCN–Transformer may fail, attention-only may prove sufficient, fixed-rate local learning may beat SEAL, or the stop-gradient boundary may leave the PCN poorly aligned with generation. Those outcomes would still be informative if the budgets, interventions, and lineage are reported honestly.

Conclusion

The proposal does not ask predictive coding to reproduce exact token history or ask attention to become a theory of purpose. River’s PCN settles multimodal evidence and task constraints. SEAL optionally modulates local plasticity when layer error departs from its recent expectation. The adapter gives the decoder a stable route to the settled state, while the stop-gradient boundary keeps the learning rules legible. Causal self-attention handles the generated prefix; cross-attention returns to the request at every token.

“Intention” earns its place only through intervention. Zero it, shuffle it, swap it, and change the evidence while holding the words fixed. If grounded behavior does not move as predicted, retire the term. If it does, the architecture has identified a useful control variable without pretending to have discovered a mind.

Attention keeps language aware of what it has said; intention keeps it answerable to why it is speaking.
